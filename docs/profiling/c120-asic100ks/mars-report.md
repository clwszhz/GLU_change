# c120 单矩阵 hcTracer 试测与统计规范

2026-10-17；GPU 0，Mars X201；hcTracer 3.5.3.18-ef9e10e。

结论：ASIC_100ks_csr 的三份 trace 均具有有效 GPU 执行时间，内核名称及次数一致，未发现跨阶段重叠或边界截断，适合进行本矩阵的阶段耗时诊断。后续矩阵仍逐一核验 trace 完整性，不把本次通过视为所有路径自动通过。

## 输入与执行固定项

- c120 冻结二进制：`f00526959a5217643f9374f1dd2af2a844f9eff4404af14c4d5c083ac3d547da`。
- 矩阵：ASIC_100ks_csr，99190 阶，578890 个原始非零；使用当前 full12 的规范化输入，按存储坐标读取，不展开对称结构，右端项为全 1，FP64。
- 输入 SHA256：`3a15a4fc5a9cc85aa84d8c88ebe7611b94462a62a3337bb91548fc28d8246f1f`。
- 原有评测器、候选代码、二进制、输入及参考解的运行前后哈希全部一致。新增文件仅位于本诊断目录及容器独立临时目录。
- 每次启动新进程，沿用缓存，不强制清除 JIT 缓存；1 次普通预热，3 次普通运行，3 次带 trace 运行。执行顺序：warmup、plain-1、trace-1、trace-2、plain-2、plain-3、trace-3。
- 命令：`hcTracer --odname trace <冻结的 lu_cmd> -i <规范化输入>`，固定 CUDA_VISIBLE_DEVICES/HIP_VISIBLE_DEVICES=0；CPU 数值库线程数为 1；不设置 LD_PRELOAD。
- 复用 GPU 0 与容器的协作锁；不清理或中断其他用户进程。GPU 0 运行前利用率为 0%，进程查询为空。本次不同时运行 ht-smi 高频采样。

## 计时与归类规范

1. 以程序原有 `timings.json` 中唯一的 `numeric_factorization` 为总窗口。该窗口末尾已有 GPU 完成同步。结构准备、建图、数值装入、scratch 清零、完整因子下载及最终 CPU 三角求解均按其原阶段归属，不向分解窗口挪入。
2. 数值分解使用原始毫秒，不使用 0.005 折算，也不使用 stdout 的 `Total GPU time` 代替分解窗口。后者含有更多工作。
3. 原始 hcTracer 时间戳和持续时间按纳秒解释。先检查其与进程 epoch 及分解窗口一致，再转换为毫秒。CPU API 调用记录和 launch 关联记录不当作 GPU 执行时长。
4. 原生内核要求 `ph=X` 且 `dur>0`；只有 launch、零时长或不完整记录时，标记归因不可用，不补成零耗时。每份 trace 检查内核次数、解的正确性及 stderr。
5. 将设备事件裁剪到分解窗口。同类事件取区间并集；另对全部设备事件取全局并集，避免多 stream 重叠时重复计时。未来若不同阶段重叠，阶段行不能直接相加。
6. 分解窗口减去全部已记录设备活动的并集，记为“未被设备活动覆盖的区间”。不能直接称为 CPU 耗时，也不能直接认定 GPU 全部空闲。
7. RL 等同时完成准备与更新的融合内核单列统计，不虚构内部拆分。panel 中的 L21/U12 是分解内部求解，与分解后 CPU 求 Ax=b 分开。
8. 每次记录原始 trace、日志、解检查、窗口、事件次数和哈希。普通运行用于报告速度；带 trace 的结果用于瓶颈诊断，不混入正式候选排名。本次 3 次重复用于试定规范；正式性能评测仍遵守原评测器要求。

全局设备活动并集平均 44.991297 ms；跨阶段重叠 0.000000 ms。本例各部分可加，是本次实际观察结果，并非对所有矩阵的假设。

三份 trace 的分解窗口均包含 1565 次内核执行；另有 1 次 4 字节状态清零和 1 次 4 字节状态回传。内核名称和次数一致，无零时长原生内核，无边界截断。7 个解均通过当前 KLU 参考解检查，相对 L2 误差最大 4.911e-15，归一化残差最大 1.037e-21。

本例耗时主要是稀疏目标更新，约占分解窗口 74.96%。优先继续细看 RL_update_tasks 的访存、查找与原子更新；这次时长统计本身不能区分三者各自占多少。panel 的四个计算部分合计 4.150823 ms，约占 8.88%。

## 文件与过程记录

- `summary.json`：所有样本、阶段归类、内核名称及次数、并集耗时。
- `stages.csv`：阶段结果表。
- `raw/runs/*`：每次 stdout/stderr、timings.json、x.dat、run.json；trace-* 子目录保留原始 hcTracer JSON。
- `trace-*-numeric-us.json`：从分解窗口裁剪并转换为微秒的时间线，可用于 Chrome/Perfetto 查看；原始 JSON 保持不变。
- `protected-before.json` / `protected-after.json`：候选、评测器和输入保护清单。
- `attempt-0-import-error/`：最初诊断脚本导入同名 evaluate 模块失败，求解尚未启动；修正独立 worker 的导入顺序后完成上述 7 次运行。
- `run-state.json`：已结束的运行标识和容器临时目录。
